# Database Reference and Local Runner

The numbered migrations are the normative M0 database contract. The runner executes them verbatim through `psql`; it does not reinterpret constraints or select an ORM.

## Local-only safety boundary

- `AXTRO_LOCAL_DATABASE_URL` must target `localhost`, `127.0.0.1`, or IPv6 loopback, and include an explicit non-secret PostgreSQL user and database name.
- Password-bearing URLs, password query parameters, implicit identities, and remote hosts fail before `psql` starts.
- The runner starts child processes from a minimal environment allowlist, forces inert password and service files, disables TLS and GSS authentication for loopback, and invokes `psql --no-password`.
- Migration receipts are stored in the non-tenant table `public.axtro_schema_migrations`, with ordered SHA-256 checksums.
- A normalized local filesystem lock serializes this runner's apply, read, and drift commands across loopback URL aliases. It does not coordinate manual or uncooperative database clients. A stale lock or a migration sentinel without its receipt fails closed for manual repair.
- The runner never creates UUIDs. Application writers use `assertApplicationUuidV7` before persistence.

## Commands

Use a password-free local PostgreSQL URL only:

```bash
export AXTRO_LOCAL_DATABASE_URL='postgresql://postgres@127.0.0.1:54329/axtro_dhos_v2'
export AXTRO_ALLOW_LOCAL_DATABASE_URL=1
pnpm db:migrate
pnpm db:drift
```

An explicitly supplied local URL requires `AXTRO_ALLOW_LOCAL_DATABASE_URL=1`. This prevents an accidental loopback tunnel from being treated as a test cluster. `db:drift` and `readAppliedMigrations` never bootstrap the receipt table: an uninitialized database fails closed. `db:drift` verifies ordered migration receipts and required PostgreSQL catalog invariants: `vector`, `pgcrypto`, the UUIDv7 version and RFC variant constraint, public tables, exact forced-RLS table and policy mappings, and append-only trigger mappings.

## Integration test

```bash
pnpm db:test
```

Without `AXTRO_LOCAL_DATABASE_URL`, the test creates PostgreSQL 17 with pgvector in a temporary local directory, performs clean and upgrade applies, compares drift fingerprints, proves domain, policy, trigger and security-function drift is rejected, verifies UUIDv7 acceptance plus UUIDv4 and invalid-variant rejection, then stops and removes the cluster. Signal interruption calls the same cleanup routine. The harness checks that the configured PostgreSQL 17 install has `vector.control` before it starts. Set `AXTRO_POSTGRES_BIN` when PostgreSQL 17 with matching pgvector is not at the default local path.

The CI job uses the same test against an ephemeral pgvector service. No migration command accepts a remote database or production credential.

## Migration boundaries

- Domain IDs are UUIDv7 generated by application code.
- Tenant-scoped tables require tenant ID, RLS, and negative tests in M0-08.
- Use transaction-local tenant context after authentication is implemented in M0-09.
- Do not store provider secrets, raw chain-of-thought, or unbounded PII JSON.
- Applied reference DDL is forward-only. There is no automatic rollback; an incident uses an explicit forward repair migration after investigation.
- `events_outbox.id` is the storage-row identifier. `events_outbox.event_id` is the UUIDv7 event identity used by tenant-scoped idempotent consumers; it is unique with `tenant_id`. A database check requires the canonical envelope to carry the same event ID and tenant ID as its row.
